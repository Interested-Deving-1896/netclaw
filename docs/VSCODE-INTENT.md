# Terminal Intent in VS Code

Run **NetClaw: Open Terminal Intent** or choose **Terminal Intent** under
Operations. Inspect retained requests, or choose a read-only or configuration
task. Select the exact endpoints, enter the task using approved secret references,
review its scope, then submit. No terminal output, editor files or credentials
are included automatically.

The first implementation uses an existing OpenClaw installation with token
authentication from its selected `.env`, an already-enabled chat-completions
endpoint, and its private pyATS testbed. It never enables the endpoint, changes
gateway authentication or imports credentials for you. Protected Hermes
Terminal Intent remains unavailable; its ordinary supported Chat workflow is
separate.

## Change control

Production configuration requests require the existing read-only ServiceNow
authority binding. The scope preview includes the exact action digest and
targets that the approved CR must match. Enter that existing CR reference after
review. Its current Implement state, independent approval, incident checks,
scope and digest are validated before admission and each work segment. The
extension does not create a CR or manufacture its approval. The existing
baseline/apply/verify and tool-level controls remain in effect.

Local/Lab is offered only when the owner has already designated endpoints through
the backend Terminal Intent **Change control** workflow. Only valid designated
SSH endpoints are selectable. The existing API creates a separate local change
record for this request before contacting the gateway. The first segment is
read-only preparation. Its exact baseline and rollback files must be present,
private, owned and bounded before the API records hashes and issues APPLY.
They must contain real prechecks and a scoped recovery plan; synthetic examples
in automated tests do not qualify an actual network change.

An explicitly read-only request cannot enter APPLY. Questions grant no
configuration authority. Selecting a Risk role or connecting an assistant does
not designate a lab endpoint. Collector authorization remains read-only. An
actual tool denial cannot be bypassed with raw SSH or a different helper.
The scoped API-created Local/Lab audit can substitute for unavailable GAIT only
under the existing AGENTS.md exception; production still requires GAIT.

## Durability and evidence

An installation-owned worker executes the existing Terminal Intent engine.
Closing VS Code, its view or the MCP connection does not stop this worker or
the gateway. The private management journal retains admission, session binding,
dispatch segments, reports and observed transcript activity. Model reports and
actual tool transcript events have distinct sources. A completed engine report
does **not** independently certify the network outcome; inspect the real device
verification and recovery evidence.

The extension retains only the pending nonce and original connection identity
while waiting for admission. On a lost reply, opening Terminal Intent again
looks up that nonce on the original installation. It never generates a new
network request automatically. The backend likewise retains nonce tombstones.

Cancelling before worker admission prevents dispatch. During execution,
cancellation stops later work segments; the current gateway/tool request may
continue. A worker crash, expired lease, lost gateway response or uncertain
authorization outcome is retained as **unknown**. The last saved engine snapshot
may precede the failure; the operation state takes precedence. Unknown Intent
work blocks new Intent admissions until authoritative recovery is established.
Inspect the exact request, gateway session, local/production change record and
live device state. Do not clear audit rows or resend with another nonce merely
to bypass this block. Automatic reconciliation from model text is not provided.

## Qualification

Mac tests cover real OpenClaw HTTP submission, façade exit, detached worker
termination, actual lease expiry, no replay and configuration preservation using
a loopback controlled provider with all runtime tools denied. Local/Lab phase,
artifact and approval tests use synthetic endpoints and explicitly synthetic
files. Real device tool enforcement, configuration/rollback qualification,
Hermes support and Windows/WSL acceptance remain separate gates. See
[Spec 150 security evidence](../specs/150-vscode-extension/evidence/security.md).
